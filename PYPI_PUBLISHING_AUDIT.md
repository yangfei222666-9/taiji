Status: trusted publishing workflow candidate, not live PyPI release evidence.

This document covers `.github/workflows/publish-to-pypi.yml`. It is valid as a
local audit template until a real GitHub release run reaches the `pypi`
environment, receives required approval, publishes to PyPI through Trusted
Publishing, and produces downloadable run evidence.

## Workflow Contract

The publish pipeline is intentionally split:

1. `build` job creates `dist/*`, checks metadata with `twine`, records hashes,
   verifies the GitHub `pypi` environment gate, and uploads the distributions
   as a short-retention artifact.
2. `publish` job downloads the distributions, verifies SHA256, enters the
   GitHub `pypi` environment, requests `id-token: write`, and publishes through
   `pypa/gh-action-pypi-publish@release/v1`.

The `id-token: write` permission must stay job-scoped to `publish`. The build
job must not receive OIDC publishing authority.

## Evidence Artifacts

The workflow emits:

| Artifact | Purpose |
|---|---|
| `pypi-dist-<sha>` | Built wheel/sdist and pre-publish evidence |
| `artifacts/sha256.txt` | SHA256 hashes for `dist/*` |
| `artifacts/environment-preflight.txt` | Required reviewer and selected-ref gate booleans |
| `artifacts/wheel-list.txt` | Human-readable distribution listing |
| `artifacts/build-metadata.json` | Workflow, commit, run, and release tag metadata |
| `pypi-publish-evidence-<sha>` | Post-publish evidence bundle after successful upload |
| `artifacts/publish-run.txt` | Boundary flags for the successful publish job |

PyPI digital attestations are generated by the publish action in Trusted
Publishing mode. They prove the publishing identity and artifact binding, not
that the package contents are safe, reproducible, or business-approved.

## Fallback Secret Rule

Fallback token publishing is not part of the default workflow. If OIDC is
temporarily unavailable, the only acceptable fallback is a PyPI project-scoped
token stored under the `pypi` GitHub Environment with a short manual TTL.

Forbidden:

- account-wide PyPI token.
- Repository-wide long-lived publish token.
- Password or token fields in `.github/workflows/publish-to-pypi.yml`.
- `skip-existing: true` on PyPI production publishing.

## Stop Rules

Return `PARTIAL` or `BLOCKED`; do not claim PyPI publishing safety if any of
the following remain true:

- PyPI project or Trusted Publisher is not verified live.
- GitHub `pypi` Environment is missing or lacks protection rules.
- Release run evidence has not been downloaded and tied to the release tag.
- A long-lived PyPI token is required for normal publishing.
- Build reproducibility has not been tested.
- The repository has unrelated dirty work outside this publishing scope.

## Correct Claim

Allowed after local verifier passes:

```text
OIDC Trusted Publishing workflow candidate is defined locally.
No long-lived PyPI publish token is required by the workflow.
PyPI live configuration and GitHub Environment protection remain external gates.
```

Not allowed:

```text
Repo is supply-chain safe.
PyPI publishing is fully verified.
Builds are reproducible.
Attestation proves package correctness.
```
